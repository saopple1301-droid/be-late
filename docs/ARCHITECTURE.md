# 設計判断メモ

元の要件は「アプリの仕様」であって「実装の完全な詳細」ではないため、以下の点は開発時に具体化したルールです。仕様変更したい場合はこのドキュメントを起点に調整してください。

## お金の流れ

1. **デポジット確保（保留）**: 待ち合わせ確定と同時に、参加者全員のカードへ `capture_method=manual` の PaymentIntent を作成し、金額を保留（オーソリ）します。この時点ではまだ請求されていません。
2. **時間通りに到着**: 保留していた PaymentIntent を `cancel` し、一切請求しません。
3. **遅刻 → 申告した時間内に到着**: デポジットは請求されません（申告した猶予の範囲内は許容）。
4. **遅刻 → 申告した時間も超過**: 保留していたデポジットを `capture`（請求確定）し、さらに同額の追加ペナルティを新規に課金します。
5. **精算**: 全参加者の状態が確定した時点（到着済み、または申告締切超過でペナルティ処理済み）で、没収された金額を他の参加者に均等分配し、Stripe Connect の Transfer で払い出します。

## ダウト予想の報酬ルール

要件には「予想するシステムを導入する」「誰が誰にダウトしたか分からない」としか書かれていないため、以下のルールを採用しました:

- 対象者が実際に遅刻し、かつ「遅刻すると思う」と予想した人だけが報酬対象（「時間通りだと思う」という予想が当たっても報酬なし。これは「疑いを当てた」ことに対するボーナスという位置づけのため）
- 報酬原資は、その人の没収額（デポジット＋追加ペナルティ）の10%を切り出したボーナスプール
- ボーナスプールは正解者（複数いる場合は均等）で分配
- 正解者がいない場合、ボーナスプールはそのまま通常の分配（他の全参加者への均等分配）に合流します（お金が消えたり増えたりしない）
- 「誰が誰を疑ったか」は `DoubtPrediction` テーブルにのみ保持し、通知や集計結果には一切含めません。精算メッセージには「合計払戻額」だけが表示されます

## 状態遷移（Meetup.status）

```
draft → collecting_deposit → doubt_phase → active → settling → completed
                                                            ↘ cancelled（ウィザード中止のみ）
```

- `doubt_job_fired` / `deadline_job_fired` / `declared_deadline_job_fired` は、APScheduler のジョブが重複実行されないようにするための冪等性フラグです
- ジョブは SQLAlchemyJobStore で永続化しているため、プロセス再起動後もスケジュールは失われません

## メンバー選択の前提

LINEのMessaging APIはグループの全メンバー一覧を取得できないため、「ボットにメッセージを送ったことがある人」だけを `GroupMember` として記録し、選択肢に出しています。待ち合わせを作る前に、全員が一度グループでボットに発言してもらう必要があります。

## 位置情報・遅刻通知・ダウト予想が個別トークで届く理由

- ダウト予想はグループ内に出すと「誰が疑われているか」が全員に見えてしまうため、必ず 1:1 のプッシュメッセージで送信します
- 遅刻の申告や到着ボタンも同様に個別トークで送り、グループには結果のアナウンスのみ流します

そのため、各参加者は **グループへの参加に加えてボットを友だち追加しておく必要があります**（そうしないと `push_message` が失敗します）。

## companion アプリ（webapp/）の位置づけ

LINE Bot の UI（グループ内でのテキスト/ボタン操作）は、複数人が同時に触るウィザードや地図表示に向かないため、同じバックエンドに REST API (`app/api.py`) を生やし、React + Vite の PWA から操作できるようにしています。

- **認証**: アプリ独自のアカウント・パスワードは作らず、LINE Login (LIFF) の ID トークンをそのまま使います（`app/auth.py` が LINE の `/oauth2/v2.1/verify` で検証し、`sub` をそのまま `User.line_user_id` として突き合わせます）。これにより LINE Bot とアプリで同一ユーザー・同一の財布（デポジット・精算）を共有できます。
- **グループの扱い**: LINE Bot はグループチャットに紐づく `Group`（`line_group_id` あり）しか作れませんが、アプリはグループチャットを介さずに `Group` を作れる必要があるため、`line_group_id` を任意化し、代わりに招待コード（`invite_code`）でメンバーを増やせるようにしました。どちらの経路で作られた `Group` も以降の挙動（待ち合わせ作成・デポジット・精算）は完全に同じです。
- **ビジネスロジックの共有**: `app/api.py` のエンドポイントは新しいロジックを持たず、LINE Bot のハンドラーと同じ `app/services/*` を呼ぶだけです。「アプリから作った待ち合わせだけ挙動が違う」という事態を避けるための意図的な設計です。
- **通知はLINEのまま**: アプリを開いていなくても遅刻や到着に気づけるよう、到着ボタンやダウト予想の督促・精算結果などのプッシュ通知は引き続き LINE の個別トークで送ります。アプリはあくまで「能動的に開いて操作する」ためのUIです。
- **位置情報**: LINE Bot 側はテキストで地図リンクを返すだけでしたが、アプリでは Leaflet + OpenStreetMap で実際の地図上にピンを表示します（APIキー不要のため）。
